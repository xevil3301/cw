# 复杂局面速判卡

## 用法

三种情况用这张卡：**时间不够、人超过两个、对手不是人。**

普通局面用 `白话速查表` 就够，这张卡是补它打不了的那三种。

---

## 卡 1 · 六十秒速判（时间不够时）

**不判断哪个最优，只判断最坏能不能扛。**

```text
问一：最坏结果我能承受吗？
  □ 能 → 往下问
  □ 不能 → 拖 或 走，别赌

问二：能不能拖一天？
  □ 能 → 拖。拖是最便宜的选项
  □ 不能 → 往下问

问三：有没有第三方会看见？
  □ 有 → 公开规则：留痕、说事实、不表态
  □ 没 → 私下规则：快、直接、给条件
```

**四格结论**：

| 能承受 | 能拖 | 结论 |
|---|---|---|
| 是 | 否 | 签，别犹豫 |
| 是 | 是 | 拖一天，走流程 |
| 否 | 是 | **拖，这是唯一正解** |
| 否 | 否 | 走，不接 |

**为什么六十秒版和完整版逻辑不同**：时间不够时最优解算不出来，但最坏结果估得出来。

## 卡 2 · 多方矩阵（人超过两个）

**只画三到四列，每格填 高／中／低。**

```text
         我      对手A   第三方B   观望者C
我       —       __       __        __
对手A    __      —        __        __
第三方B  __      __       —         __
观望者C  __      __       __        —
```

**只读两条**：

- **依赖最少的那一格 = 定价者**（他不需要谁，所以他定条件）
- **最先动的那一方 = 定义局面的人**（不是最强的，是最快的）

**三类观望者，先分清再动作**：

```text
□ 传话人：两边说话，两边不站 → 别通过他传话
□ 等结果的人：谁赢跟谁 → 给他"现在表态不亏"的理由
□ 依附者：已站队但没公开 → 别逼他公开，逼了他会回去表忠心
```

**两条操作规则**：

1. **三方以上，不要一次动两个人**——你一同时动 A 和 B，他们就会结盟
2. **每动一步，重画矩阵**——C 的立场会随 A、B 的动作变

## 卡 3 · 对手不是人（平台／算法／流程）

```text
先分类：
  □ 有意图的人 → 用心理战（12、13、14）
  □ 有规则的组织 → 用程序战（21 篇 1–8 节）
  □ 有算法的系统 → 用接口战（下面四步）
```

**接口战四步**：

```text
1. 找维护者
   这个规则谁在维护？运营／审核／风控／法务，哪一个？
   → 找到人，问题就从"系统"变回"人"

2. 找例外条款
   有什么情况它会人工复核？
   → 例外路径一般不写在明面上

3. 找合规压力
   它怕什么：监管／媒体／大客户／法律诉讼
   → 把你的问题翻译成它必须回应的语言

4. 把成本外部化
   它对你的伤害，是它把成本转嫁给了你
   → 想办法让成本回到它身上
```

**一条判断**：**如果这件事对它成本为零，它永远不改。** 你要做的不是说服它，是提高它的成本。

---

## 卡 4 · 反馈环（每动一步都要重来）

**所有一次性模型都错在同一个地方：以为算一次就够。**

```text
动一次
  ↓
看三步：
  ① 对手做了什么（不是说了什么）
  ② 观望者的立场变了没有
  ③ 有没有新的人进场
  ↓
重画矩阵
  ↓
再动
```

**规矩**：**一次只动一个变量。** 同时改三件事，你无法判断哪件起了作用，也无法在出错时撤回。

---

## 一句话

**复杂局面的解法不是"算得更细"，是"算得更勤"。**

三方能打，靠的是每步重画；系统能打，靠的是找维护者；时间不够能打，靠的是只算最坏。
